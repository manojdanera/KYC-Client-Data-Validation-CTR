# KYC Client Data Validation & CTR Flagging

A synthetic case study that simulates how client data is collected, verified and reported before it reaches a client-facing team, including the AML checks that depend on it (Currency Transaction Reports and structuring red flags).

**Tools:** Python (Pandas), SQL (SQLite/MySQL-style), Excel-ready CSV outputs

> **Synthetic data only.** All clients and transactions are generated by `python/generate_data.py` with deliberately injected errors. No real, customer or confidential data is used. The high-risk country list is illustrative.

## Business problem
Incomplete, duplicate or invalid client records create compliance risk: a Currency Transaction Report (CTR) cannot be filed accurately if the client's identity data is wrong. This project builds repeatable checks that catch those problems first and escalate them.

## Dataset
- 5,060 client records (5,000 unique clients + 60 injected duplicates)
- 25,175 transactions (cash deposits/withdrawals, wires, checks)

## Checks performed
| Client data (KYC) | Transaction / AML |
|---|---|
| Missing mandatory fields (name, DOB, ID number, address, country) | CTR candidates: cash in or out above 10,000 per client per day (aggregated) |
| Duplicate records (same ID number) | Structuring: 2+ cash deposits of 9,000-9,999 within 3 days |
| Invalid ID format, invalid DOB (future / under 18) | Orphan transactions (client not in master data) |
| Expired ID documents, invalid country codes, malformed email | CTRs blocked by incomplete client data |
| High-risk country flag for enhanced due diligence review | |

## How to run
```
pip install pandas numpy
python python/generate_data.py
python python/validate_and_flag.py
python python/sql_crosscheck.py
```

## Outputs (`data/`)
`clients_clean.csv` (de-duplicated, standardised, Ready/Escalate status), `exceptions_clients.csv` (issue log by severity), `ctr_candidates.csv`, `structuring_alerts.csv`, `data_quality_kpis.csv`

## Recommended controls
1. Block onboarding when mandatory fields are missing.
2. Validate ID format, DOB and expiry at the point of entry.
3. Run duplicate checks on ID number before creating a record.
4. Fix client data before preparing any CTR.
5. Route structuring patterns and high-risk countries to compliance review.
6. Track exception counts by severity every cycle.
